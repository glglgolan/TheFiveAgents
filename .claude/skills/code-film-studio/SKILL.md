# Code Film Studio

A reusable pipeline for building a short 2D animated film where every visual and every sound is
**generated by code your agents write and run locally** — zero generative AI models anywhere in the
pipeline. Built from a real production run (60s / 6 shots / 5 characters / 2 sets / full dialogue,
music and SFX, CPU-only render). This skill exists to make the *second* film dramatically cheaper
than the first: it ships the reusable scaffold, the orchestration playbook, and the model-tier
guidance that the first run had to discover the hard way.

## Before anything else: set expectations with the user

This is an expensive, multi-agent, multi-hour undertaking even with every optimization below — not
a quick request. Before scaffolding anything, tell the user (in one short message, then proceed):
- Realistic length for a first pass: 30–90 seconds. Longer is possible but scales cost roughly linearly.
- It will spawn a roster of subagents (typically 8–15) working in parallel across two phases.
- Estimated cost: see `reference/ORCHESTRATION.md` → "What this actually costs" for the measured
  baseline and the expected improvement from the levers in this skill. Give the user that order-of-
  magnitude estimate, not a false-precision number.
- It needs no GPU and no paid API for image/video/voice — cost is entirely in agent tokens and CPU
  render time.

If the user wants something faster/cheaper and doesn't specifically need "zero generative models",
say so and point back to the team's normal image/video pipeline (יובל + the-video-man's Kling/
Seedance path) instead of running this.

## Machine prerequisites (check once, first project on a machine)

- Node + npm, Python 3 with `numpy`, `scipy`, `soundfile`, `pedalboard`, `pyloudnorm`, `cmudict`,
  `imageio-ffmpeg` (all pip-installable, no Homebrew/ffmpeg system install needed — ffmpeg comes from
  `imageio-ffmpeg`).
- macOS `say` for classic (non-neural) voices — list them with `say -v '?'`.
- No GPU use anywhere — the render script forces `--gl=swiftshader` (CPU-only).

## Workflow

1. **Scaffold**: `bash scripts/scaffold.sh <target_dir> "<Film Title>"`. This creates the project
   structure and copies the reusable library (`src/lib/*`, `audio/mix.py`, configs) — don't hand-write
   these from scratch; they're already general-purpose.
2. **Write the creative spec** (orchestrator does this, not an agent): fill `bible/style.json` (art
   direction, palette, format), `src/data/timeline.json` (shots, dialogue with frame windows, events
   with exact frames, a music-cue paragraph), and `bible/BRIEF.md` (start from
   `reference/BRIEF.template.md`, fill in the absolute rules + project root + look, keep the
   character/set contracts as-is — they're generic).
3. **Run the production**: follow `reference/ORCHESTRATION.md` exactly — it covers model tiers per
   role (the main cost lever), phase order, iteration caps, report brevity, and the render step.
4. **Mix + render + verify**: `python audio/mix.py`, then `bash scripts/render.sh <target_dir>`,
   then pull a contact sheet (`ffmpeg -vf "select='not(mod(n\,30))',scale=320:-1,tile=8x6"`) and
   actually look at it before calling the film done.
5. **Optional subtitles**: see `reference/ORCHESTRATION.md` Phase 6.

## Files in this skill

- `templates/` — the reusable project scaffold (package.json with the render script already pointed
  at the fast CPU engine, tsconfig, `src/lib/{style,motion,rng,fx,types,visemes}.ts(x)`, `audio/mix.py`,
  `src/{index,Film,Root,Subtitles}` skeletons, `bible/style.template.json`,
  `src/data/timeline.template.json`).
- `scripts/scaffold.sh` — instantiates `templates/` into a new project directory.
- `scripts/render.sh` — bundle + CPU-only render, engine choice already decided (see below).
- `reference/BRIEF.template.md` — the per-agent brief every asset/shot agent reads first.
- `reference/ORCHESTRATION.md` — the full playbook: model tiers, phase order, iteration caps,
  report-brevity rule, the render-engine finding, and a real cost baseline.

## Known findings already baked in — don't rediscover these

- **Render engine**: `--gl=swiftshader` (CPU-only) measured ~7x faster than `--gl=swangle`
  (also CPU-only) for pixel-identical output on this pipeline. `scripts/render.sh` already uses it.
- **Lip sync without any ML**: derive phoneme timing from `cmudict` (or a letter-to-sound fallback),
  distribute across each rendered line's actual voiced segments, map to visemes A–H,X, add an
  RMS-energy layer for jaw openness. See `src/lib/visemes.ts` + `src/lib/types.ts` in `templates/`.
- **Dialogue voices**: macOS `say` classic (non-neural) voices only — never "Enhanced"/"Premium"/Siri
  voices, which are neural TTS and break the "no generative models" constraint.
