# test-driven-development

## מה זה עושה

**חוק ברזל:** כתוב בדיקה ראשונה. ראה אותה נכשלת. כתוב קוד מינימלי לעבור אותה.

מחזור RED-GREEN-REFACTOR:
1. כתוב בדיקה שנכשלת
2. כתוב קוד מינימלי לעבור
3. Refactor תוך שמירת בדיקות ירוקות

Anti-pattern: כתיבת קוד לפני בדיקה → מחיקה והתחלה מחדש.

## שייך ל

כל הצוות — מחויב לכל feature ו-bugfix.
